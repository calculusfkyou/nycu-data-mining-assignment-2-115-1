# NYCU Data Mining HW2 — Anomaly Detection on VisA

Image-level industrial defect detection on the VisA dataset with a three-tier comparison:

| Tier | Method | Code |
|---|---|---|
| T1 naive baseline | mean-normal-image template, mean absolute difference | `methods.TemplateDiff` |
| T2 primary method | PaDiM-style per-location Gaussian (WideResNet-50, 200 random channels) | `methods.PaDiM` |
| T3 strong reference | PatchCore (WideResNet-50, 1 % greedy coreset) | `methods.PatchCore` |

All tiers share one fixed split, are fitted on normal images only, and pick their threshold τ on a
validation set (best F2). The test set is read once, after every model and threshold is fixed.

## Results (test, 12 objects, mean ± std over 3 seeds)

| Method | PR-AUC | ROC-AUC | F1 | FPR@τ | prec@1 % | ms / image |
|---|---|---|---|---|---|---|
| T0 predict all normal | 0.442 | 0.500 | 0 | 0 | – | – |
| T1 template | 0.702 | 0.762 | 0.693 | 0.465 | 0.023 | 0.12 (CPU) |
| T2 PaDiM | 0.801 ± 0.007 | 0.828 ± 0.008 | 0.733 ± 0.007 | 0.332 ± 0.012 | 0.037 ± 0.005 | 7.38 |
| T3 PatchCore | **0.885 ± 0.002** | **0.902 ± 0.002** | **0.806 ± 0.009** | **0.174 ± 0.021** | **0.148 ± 0.044** | 11.72 |

- T3 − T2 PR-AUC = +0.084, paired bootstrap 95 % CI [0.065, 0.102], Wilcoxon p = 0.003 over the 12 objects.
- prec@1 % is the share of alerts that would be real defects at a 1 % production defect rate.
- Latency: RTX 4060 Ti, batch 1, feature extraction included.
- Without the three objects whose anomalies show a capture-condition shortcut (cashew, pcb1, pcb2), the
  ranking is unchanged (PR-AUC 0.655 / 0.785 / 0.874).

Sources: `results/stage6_main/summary.csv`, `latency.csv`, `results/stage8_analysis/significance.csv`.
Ablations: `results/stage7_ablation/ablation_summary.csv`. Write-ups: `reports/progress.md`
(Traditional Chinese progress report) and `reports/sec3-8.md` (English draft of paper §3–§8).

## Setup

Python 3.9+ and an NVIDIA GPU. Install the CUDA build of torch together with the other packages:

```bash
python -m venv .venv
```

```bash
.venv/Scripts/python.exe -m pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cu126
```

(On Linux / macOS use `.venv/bin/python`.) `requirements.txt` pins the versions used for stages 1–4
(Python 3.9.1, torch 2.8.0+cu126). Stages 5–8 were run with Python 3.12.8 and torch 2.15.0+cu132
(`results/stage6_main/environment.csv`); the split and the EDA tables reproduced identically under both.

## Data

VisA (Zou et al., ECCV 2022; https://github.com/amazon-science/spot-diff) is released under
**CC BY 4.0**. The dataset itself is not in this repository (1.9 GB; `data/` is git-ignored — how the
team will ship it is still to be decided). `src/data.py` recreates everything needed:

1. downloads `VisA_20220922.tar` from the official S3 link into `data/` and extracts it to `data/VisA/`
   (both steps are skipped when the files already exist);
2. rebuilds `splits/visa_split.csv` from the official `split_csv/1cls.csv` with seed 0 and checks it.

The committed `splits/visa_split.csv` (md5 `436809f3fdb8a8d0f2a40b093e51ab58`) is the split used for every
result; rebuilding it gives the same file.

| split | normal | anomaly | use |
|---|---|---|---|
| train | 7,705 | 0 | fit the models |
| val | 954 | 240 | choose τ and hyperparameters |
| contam | 0 | 240 | training-contamination ablation only |
| test | 962 | 720 | final evaluation, read once |

## Reproduce

Run everything in stage order (about 1.5 h on an RTX 4060 Ti 8 GB with 32 GB RAM, plus the download;
times below are from that machine):

```bash
PY=.venv/Scripts/python.exe bash reproduce.sh
```

| Step | Command | Output | Time |
|---|---|---|---|
| data + split | `src/data.py` | `data/VisA/`, `splits/visa_split.csv` | download |
| feature cache | `src/features.py` | `cache/` (~15 GB, git-ignored) | ~6 min |
| EDA (§3–§4) | `src/eda.py` | `results/stage4_eda/` | not timed |
| self-check + quick run | `src/methods.py`, `src/run.py --quick` | `results/stage5_quick*/` | ~5 min |
| val-only search | `src/run.py --search` | `results/stage6_main/search_val.csv` | ~45 min |
| main run (§7) | `src/run.py` | `results/stage6_main/` | ~18 min |
| latency | `src/run.py --latency pcb1` | `results/stage6_main/latency.csv` | ~1 min |
| ablations (§7) | `src/run.py --ablation` | `results/stage7_ablation/` | ~3 min |
| analysis (§5, §8) | `src/analyze.py` | `results/stage8_analysis/` | ~6 min |

`src/run.py --search` must finish before the main run: the main run, ablations and analysis read the
chosen settings from `search_val.csv`. One file is not regenerated by the script:
`results/stage5_quick_smooth/val_padim_raw_vs_smooth.csv` came from a one-off val comparison during stage 5;
Ablation A4 (`results/stage7_ablation/`) repeats the smoothing comparison with the final settings.

## Layout

```
src/data.py        download, fixed split, Dataset (224 x 224, no centre crop)
src/features.py    WideResNet-50 layer2/3/4 feature cache, one float16 file per class and layer
src/eda.py         §3 tables and samples, §4 feature analysis, centre-crop and capture-condition checks
src/methods.py     Tier 1/2/3 with fit() / score() -> (image score, heatmap); synthetic self-check
src/run.py         metrics, best-F2 tau, val search, main run, latency, ablations
src/analyze.py     pipeline figure, significance, failure cases, heatmaps, H1/H2, practical impact
splits/            the fixed split
results/stage*/    every table and figure used in the reports
reports/           progress report and paper draft
CHECKLIST.md       implementation / review checklist per stage
```
